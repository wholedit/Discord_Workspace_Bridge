# M1 가이드: 창 없이 실행·자동 재시작·진행 표시

M1부터는 워크스페이스를 **터미널 창 없이** 백그라운드에서 실행합니다. 이 실행 관리자(Supervisor)가 하는 일은 다음과 같습니다.

- 워크스페이스마다 `claude`를 창 없이(의사 터미널) 띄웁니다.
- `claude`가 종료되면 **자동으로 다시 시작**합니다. 실패가 반복되면 5초 → 15초 → 30초 … 최대 5분까지 간격을 늘립니다.
- 워크스페이스마다 **자기 세션 ID를 기억**해서 재시작해도 그 대화만 이어 갑니다(`--resume`). M0의 `--continue`가 그 폴더의 다른 대화를 이어받던 문제가 없어졌습니다.
- 작업 중이면 해당 채널에 **진행 상태 메시지**를 하나 올리고 계속 갱신합니다(`🟡 Running · 0m 42s · tools 7` + 최근 도구 목록). 알림 없이 조용히 갱신되고, 끝나면 `🟢 Done`으로 바뀝니다.
- 시작하기 전에 각 봇 토큰이 아직 유효한지 확인합니다. 토큰을 재발급했는데 다시 등록하지 않았다면 그 워크스페이스는 시작하지 않고 이유를 알려 줍니다.

## 1. 처음 한 번: 폴더 신뢰 확인

`claude`는 폴더를 처음 열 때 "이 폴더를 신뢰하는지" 묻습니다. 보안 확인이라 실행 관리자가 대신 답하지 않습니다. 아직 신뢰하지 않은 폴더는 상태가 `🔐 needs-trust`로 표시되고, 실행 관리자가 그 워크스페이스만 멈춥니다.

해당 워크스페이스를 보이는 창으로 한 번 열어 직접 승인하세요.

```bash
npm run launch -- 워크스페이스이름
```

승인했으면 그 탭은 닫습니다. M0 테스트 때 이미 연 폴더는 이 단계가 필요 없습니다.

> **같은 워크스페이스를 창 모드(`launch`)와 실행 관리자(`npm start`)로 동시에 실행하지 마세요.** 같은 봇이 두 번 접속합니다.

## 2. 실행

M0 때 열어 둔 Windows Terminal 탭은 먼저 모두 닫습니다. 그다음:

```bash
npm start
```

- 창이 열리지 않습니다. 이 터미널에 상태 기록이 출력됩니다.
- 워크스페이스마다 `🟢 Discord plugin connected (#채널)`이 나오면 준비된 것입니다. 플러그인이 시작될 때마다 `bun install`을 하기 때문에 처음에는 30초 정도 걸릴 수 있습니다.
- 끄려면 이 터미널에서 `Ctrl+C`를 누릅니다. 모든 워크스페이스가 함께 종료됩니다.

다른 터미널에서 현재 상태를 볼 수 있습니다.

```bash
npm run status
```

특정 워크스페이스만 실행하거나, 새 대화로 시작할 수도 있습니다.

```bash
npm start -- web
```

```bash
npm start -- --fresh=web
```

## 3. 권한 모드 (기본: 자동)

워크스페이스마다 Claude가 작업할 때 얼마나 자주 승인을 받을지 정할 수 있습니다.

| 모드 | 동작 |
|---|---|
| `auto` (기본) | 안전 분류기가 위험이 낮은 작업은 스스로 승인하고, 위험한 작업만 DM으로 승인을 요청 |
| `manual` | 파일 수정과 명령 실행마다 DM으로 승인 요청 (가장 안전) |
| `acceptEdits` | 파일 수정은 자동 승인, 명령 실행은 DM으로 승인 요청 |
| `plan` | 계획만 세우고 아무것도 바꾸지 않음 |

현재 모드 보기:

```bash
npm run mode
```

바꾸기 (예: `web`을 수동 모드로):

```bash
npm run mode -- web manual
```

실행 관리자가 켜져 있으면 몇 초 안에 그 워크스페이스만 다시 시작해서 적용합니다. 대화는 이어지지만, 진행 중이던 작업은 중단됩니다. 기본으로 되돌리려면 `npm run mode -- web auto`를 실행하세요.

> 원격 조작이라 모든 확인을 건너뛰는 `bypassPermissions`와 `dontAsk`는 지원하지 않습니다. 폰에서 모드를 바꾸는 명령(`/mode`)은 M2의 관리용 봇에서 제공합니다.

## 4. M1 완료 체크리스트

| # | 해볼 것 | 기대 결과 | ✓ |
|---|---|---|---|
| 1 | `npm start` | 터미널 창 없이 각 봇이 온라인, 로그에 `plugin connected` | |
| 2 | 폰에서 파일을 읽거나 명령을 실행하는 작업 요청 (예: `src 폴더 구조를 설명해줘`) | 채널에 진행 상태 메시지가 생기고 도구 목록이 갱신되다가 `🟢 Done`으로 바뀜. 진행 메시지는 폰 알림을 울리지 않음 | |
| 3 | `npm run mode -- web manual` 후 파일 수정 요청 | 승인 DM이 오고, 진행 메시지가 `🟠 Waiting for approval`로 바뀜 → Allow 후 다시 진행 | |
| 4 | 간단한 질문 (도구를 안 쓰는 답) | 진행 메시지 없이 답장만 옴 | |
| 5 | 작업 관리자에서 해당 워크스페이스의 `claude.exe`를 강제 종료 | 로그에 `restarting` → 몇 초 뒤 다시 실행 → 봇이 다시 온라인 | |
| 6 | 5번 후 폰에서 이전 대화를 이어서 질문 | 재시작 전 대화를 기억함 | |
| 7 | `npm run status` | 각 워크스페이스 상태와 재시작 횟수 표시 | |
| 8 | `Ctrl+C`로 종료 | 모든 봇이 오프라인이 되고 `claude`/`bun` 프로세스가 남지 않음 | |
| 9 | `npm start` 다시 실행 후 대화 이어서 질문 | 같은 대화를 이어 감 | |

## 문제 해결

- **`needs-trust`**: 위 1번(폴더 신뢰 확인)을 하세요.
- **`failed: bot token is no longer valid`**: 토큰을 재발급한 봇입니다. `npm run add`로 같은 봇을 새 토큰으로 다시 등록하세요.
- **`plugin failed`가 반복됨**: `npm run status`의 메시지를 확인하세요. 연결에 한 번 실패하면 `claude`가 약 15분 동안 자동 재시도를 건너뛸 수 있습니다. 이때는 `npm run launch -- 이름`으로 열어 `/mcp`에서 직접 다시 연결해 보면 원인을 바로 볼 수 있습니다.
- **"The supervisor is already running"**: 이미 실행 중인 실행 관리자가 있습니다. 그 터미널에서 `Ctrl+C`로 끄세요. 그 프로세스가 이미 없는데도 이 메시지가 나오면 안내된 `supervisor.pid` 파일을 지우세요.
- **진행 메시지가 안 생김**: 실행 관리자(`npm start`)로 실행했을 때만 생깁니다. 창 모드(`launch`)에서는 꺼져 있습니다.
