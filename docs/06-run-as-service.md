# 6. 계속 켜 두기 (백그라운드·자동 시작·절전)

폰에서 쓰려면 PC가 켜져 있고, 로그인돼 있고, 실행 관리자가 돌고 있어야 합니다.

## 실행 방법 세 가지

| 방법 | 언제 |
|---|---|
| `npm start` | 터미널에서 실행. 로그가 바로 보임. `Ctrl+C`로 종료 |
| `npm run start:bg` (설정 페이지의 "백그라운드로 시작") | 창 없이 실행. 로그는 `npm run logs` |
| 자동 시작 | Windows에 로그인하면 자동으로 백그라운드 실행 |

어떤 방법으로 켰든 `npm run stop`(또는 설정 페이지의 **중지**)으로 끌 수 있고, `npm run status`로 상태를 볼 수 있습니다. 실행 관리자는 한 번에 하나만 돕니다 (두 번 켜면 거절).

## 자동 시작 (Windows)

설정 페이지 **2. 실행 → PC를 켜면 자동 시작 → 켜기**, 또는:

```bash
npm run autostart -- on
```

- 작업 스케줄러에 `workspace-bridge` 작업을 **현재 사용자용**으로 등록합니다. 관리자 권한도, 비밀번호 저장도 필요 없습니다.
- **Windows에 로그인하고 30초 뒤** 시작합니다. 그때 검은 창이 1~2초 보였다가 사라지는데, 백그라운드로 넘겨 주는 시작 프로그램입니다.
- 부팅만 하고 로그인하지 않으면 시작하지 않습니다 (`claude`가 내 로그인 세션을 쓰기 때문). **화면 잠금 상태는 괜찮습니다.**
- 확인: `npm run autostart` / 끄기: `npm run autostart -- off`
- 저장소 폴더를 옮겼다면 다시 켜세요. 설정 페이지에 "another copy"로 표시됩니다.
- **중지와 자동 시작은 별개**입니다. `npm run stop`으로 꺼도 다음 로그인 때 다시 켜집니다.

### 업데이트로 재부팅된 뒤에도 돌아오게
Windows 업데이트가 밤사이 재부팅하면 로그인 화면에서 멈춥니다. 다음을 켜 두면 업데이트 후 자동으로 로그인(후 잠금)됩니다.

**설정 → 계정 → 로그인 옵션 → "업데이트 또는 다시 시작한 후 내 로그인 정보를 사용하여 자동으로 설정 완료"**

재부팅 후 다시 켜지면 `#control`에 🟢 Supervisor online이 옵니다. 이 알림이 안 오면 PC가 로그인 화면에 멈춰 있을 가능성이 큽니다.

## 절전 방지

실행 관리자가 도는 동안 **PC가 잠자기에 들어가지 않게** 합니다 (화면은 꺼질 수 있음). 잠자기 상태에서는 폰에서 보낸 메시지를 받을 수 없기 때문입니다. 실행 관리자가 꺼지면 원래 전원 설정으로 돌아갑니다.

- 확인: `/ping`의 ☕ sleep prevention on, 또는 `npm run status`
- 노트북 덮개 닫기, 전원 버튼, 직접 절전은 막지 않습니다. 노트북이면 **제어판 → 전원 옵션 → 덮개를 닫으면: 아무 것도 안 함**으로 두세요.
- 끄기: 환경 변수 `WSB_ALLOW_SLEEP=1`을 두고 시작

## 로그

- 백그라운드 실행 로그: `~/.workspace-bridge/logs/supervisor.log` (5MB를 넘으면 `.1`로 하나 보관)
- 보기: `npm run logs` (마지막 60줄), `npm run logs -- 200`
- 워크스페이스별 최근 화면: 폰에서 `/logs ws:web`
