# M3 가이드: 설정 페이지, 백그라운드 실행, 자동 시작

## 1. 설정 페이지

```bash
npm run setup
```

브라우저에 설정 페이지가 열립니다. 안 열리면 터미널에 나온 링크를 이 PC의 브라우저에 붙여 넣으세요.

| 칸 | 하는 일 |
|---|---|
| 1. 이 PC 점검 | Node, Claude Code 설치·로그인, Bun, 공식 디스코드 플러그인 확인. 빠진 것은 고치는 방법 표시 |
| 2. 실행 | 실행 관리자 상태, 백그라운드로 시작·다시 시작·중지, 절전 방지 상태, PC를 켜면 자동 시작 |
| 3. 워크스페이스 | 목록과 실시간 상태, 추가(단계별 안내), 폴더 신뢰 확인, 삭제 |
| 4. 관리용 봇 | `#control` 봇 추가·바꾸기·삭제 |

**워크스페이스 추가 순서** (페이지가 한 단계씩 안내합니다)

1. 봇 만들기: 개발자 포털 링크
2. 토큰 붙여 넣기: 바로 검증, 봇 이름 표시 (토큰은 화면에 보이지 않고 페이지로 다시 오지 않음)
3. 봇 설정 확인: Message Content Intent 켜짐·Public Bot 꺼짐을 **자동으로 다시 확인** (설정 화면 직접 링크)
4. 서버에 초대: 초대 버튼 → 봇이 들어오면 **자동으로 다음 단계**
5. 채널 고르기: 목록에서 선택 (다른 워크스페이스·관리용 봇이 쓰는 채널은 선택 불가)
6. 작업 폴더: 경로 입력 또는 **찾아보기…** (PC에 폴더 선택 창이 뜸)
7. 내 디스코드 계정: 서버 소유자가 기본값
8. 이름·권한 모드 → 저장
9. 첫 실행: 실행 관리자가 켜져 있으면 **재시작 없이 몇 초 안에 시작**됩니다. 처음 쓰는 폴더라 🔐가 뜨면 **PC에서 신뢰 확인 창 열기** → 새 창에서 `Yes, I trust this folder` → `/exit`. 그러면 자동으로 다시 시작되고, 봇이 온라인이 되면 ✅ 표시

다 끝나면 **설정 끝내기**를 누르세요. 페이지를 그냥 닫아도 20분 뒤 자동으로 닫힙니다.

### 안전장치
- 페이지는 `127.0.0.1`(이 PC)에서만 열립니다. 주소에 들어 있는 임의의 키가 없으면 아무 동작도 하지 않고, 다른 웹사이트에서 보내는 요청은 거절합니다.
- 봇 토큰은 `~/.workspace-bridge` 아래에만 저장됩니다.
- 폴더 신뢰 질문은 이 프로그램이 대신 답하지 않습니다. 사람이 직접 답합니다.

## 2. 백그라운드 실행 (창 없이)

| 명령 | 하는 일 |
|---|---|
| `npm start` | 터미널에서 실행 (Ctrl+C로 종료) |
| `npm run start:bg` | 창 없이 백그라운드로 실행. 설정 페이지의 "백그라운드로 시작"과 같음 |
| `npm run stop` | 실행 중인 실행 관리자 종료 (터미널·백그라운드 모두) |
| `npm run status` | 상태 보기 |
| `npm run logs` | 백그라운드 로그 마지막 60줄 (`~/.workspace-bridge/logs/supervisor.log`, 5MB 넘으면 `.1`로 교체) |
| `npm run trust -- web` | 폴더 신뢰 확인 창 열기 (닫히면 해당 워크스페이스 자동 재시작) |

실행 관리자가 켜져 있는 동안에는 다음이 **재시작 없이** 바로 반영됩니다: 워크스페이스 추가·삭제·봇 교체(설정 페이지, `npm run add`/`remove`), 권한 모드 변경, 관리용 봇 추가·교체.

### 절전 방지
실행 관리자가 켜져 있는 동안 **PC가 잠자기에 들어가지 않습니다** (화면은 꺼질 수 있음). 잠자기 상태에서는 폰에서 보낸 메시지를 받을 수 없기 때문입니다. 실행 관리자가 꺼지면 원래대로 돌아갑니다. `/ping`과 `npm run status`에 상태가 표시됩니다.
- 노트북 덮개를 닫거나 직접 절전을 누르는 것은 막지 않습니다.
- 끄려면 환경 변수 `WSB_ALLOW_SLEEP=1`을 설정하고 시작하세요.

## 3. PC를 켜면 자동 시작 (Windows)

설정 페이지의 **2. 실행 → PC를 켜면 자동 시작 → 켜기**, 또는:

```bash
npm run autostart -- on
```

- Windows 작업 스케줄러에 `workspace-bridge` 작업을 **현재 사용자용**으로 등록합니다. 관리자 권한과 비밀번호 저장이 필요 없습니다.
- **Windows에 로그인하고 30초 뒤** 시작됩니다. 로그인 직후 1~2초 동안 검은 창이 잠깐 보였다가 사라지는데, 백그라운드로 넘겨 주는 시작 프로그램입니다.
- 부팅만 하고 로그인하지 않은 상태에서는 시작되지 않습니다 (claude가 내 Windows 로그인 세션을 쓰기 때문). 화면 잠금 상태는 괜찮습니다.
- Windows 업데이트로 재부팅된 뒤에도 자동으로 로그인되게 하려면: **설정 → 계정 → 로그인 옵션 → "업데이트 또는 다시 시작한 후 내 로그인 정보를 사용하여 자동으로 설정 완료"** 켜기
- 상태 확인: `npm run autostart` / 끄기: `npm run autostart -- off`
- 저장소 폴더를 옮겼다면 다시 `on` 하세요 (설정 페이지에 "다른 폴더로 등록됨"이 표시됩니다).

### 자동 시작 테스트 (다른 PC에서)

| # | 해볼 것 | 기대 결과 | ✓ |
|---|---|---|---|
| A1 | `npm run autostart -- on` | "Auto-start is on" | |
| A2 | 작업 스케줄러(`taskschd.msc`) → 작업 스케줄러 라이브러리 | `workspace-bridge` 작업, 트리거 "로그온할 때", 사용자 = 내 계정 | |
| A3 | PC 재시작 → 로그인 → 1분 기다리기 | `npm run status`에 running, `#control`에 🟢 Supervisor online | |
| A4 | 폰에서 워크스페이스 채널에 메시지 | 평소처럼 답장 | |
| A5 | `npm run logs` | 시작 로그가 보임 | |
| A6 | 오래 그대로 두기 (평소 절전 시간보다 길게) | PC가 잠자기에 들어가지 않음, 폰에서 여전히 동작 | |
| A7 | `npm run autostart -- off` → 재시작·로그인 | 자동으로 시작되지 않음 | |

**회사 PC 참고:** 보안 프로그램이 서명 없는 실행 파일을 막는 환경이 있습니다. 그래서 백그라운드 실행은 별도 실행 파일 없이 Node로 처리합니다. 절전 방지(`awake.exe`)나 bun 래퍼(`bun.exe`)가 막히면 보안 담당자에게 예외를 요청하거나, 절전 방지는 `WSB_ALLOW_SLEEP=1`로 끄고 Windows 전원 설정에서 절전을 "안 함"으로 두세요.
